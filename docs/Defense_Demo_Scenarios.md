## Defense Demo Scenarios

Документ для предзащиты: последовательность демонстрации, критерии успеха и чеклист показа.

## 1) Подготовка перед демонстрацией

1. Проверить наличие `.env` и обязательных ключей.
2. Убедиться, что зависимости установлены (`uv sync --group dev`).
3. Поднять MCP-серверы в отдельных терминалах:
  - `python -m servers.market_server.server`
  - `python -m servers.news_server.server`
  - `python -m servers.analytics_server.server`
4. Поднять один из UI:
  - CLI: `python -m ui.cli chat`
  - при необходимости компактного показа: `python -m ui.cli chat --answer-depth compact`
  - или Streamlit: `streamlit run ui/streamlit_app.py`

## 2) Демонстрационные сценарии (по ТЗ)

### Сценарий 1: Market-only

- **Запрос**: `Покажи котировку SBER`
- **Ожидаемое поведение**:
  - используется `market_server`;
  - в ответе есть рыночный блок, ошибок нет.
- **Критерий успеха**:
  - сформирован `final_answer`, `error_count` не растет критически.

### Сценарий 2: News-only

- **Запрос**: `Последние новости по Газпрому`
- **Ожидаемое поведение**:
  - используется `news_server`;
  - присутствуют новости с trust/sentiment.
- **Критерий успеха**:
  - получен итоговый ответ и список новостей.

### Сценарий 3: Risk assessment

- **Запрос**: `Оцени риск портфеля demo_portfolio`
- **Ожидаемое поведение**:
  - используется `analytics_server`;
  - возвращаются риск-метрики (VaR/CVaR/volatility/HHI).
- **Критерий успеха**:
  - присутствует блок аналитических метрик.

### Сценарий 4: Stress test

- **Запрос**: `Проведи стресс-тест портфеля demo_portfolio при падении IMOEX на 20%`
- **Ожидаемое поведение**:
  - используется `run_stress_test`;
  - сценарий интерпретирован как `index_drop`, рассчитаны потери.
- **Критерий успеха**:
  - ответ содержит итоговые потери и сравнение с VaR.

### Сценарий 5: Комплексный

- **Запрос**: `Оцени риск портфеля demo_portfolio с учетом новостей нефтегаза и котировки GAZP`
- **Ожидаемое поведение**:
  - задействуются `market + news + analytics`;
  - итог формируется после нескольких шагов planner;
  - в блоке "Основные показатели" данные сгруппированы по подзаголовкам.
- **Критерий успеха**:
  - все три группы данных отражены в финальном ответе.

### Сценарий 6: Investment decision intent

- **Запрос**: `Стоит ли сейчас покупать Сбербанк с учетом новостей и риска?`
- **Ожидаемое поведение**:
  - запрос распознается как `investment_decision_intent`;
  - ассистент использует аналитику рынка/новостей/риска, но не дает прямую команду `покупать` или `продавать`;
  - финальный блок формулируется как взвешенный вывод с оговоркой, что это не инвестиционная рекомендация.
- **Критерий успеха**:
  - ответ полезен для клиента/комиссии, но не нарушает ограничение на отсутствие прямой рекомендации.

## 3) Fallback-кейсы (устойчивость)

### Частичная недоступность news источников

- **Как показать**: отключить/замокать часть RSS.
- **Ожидаемое поведение**:
  - граф не падает;
  - предупреждение в `warnings`;
  - финальный ответ остается сформированным.

### Ошибочный analytics шаг

- **Как показать**: спровоцировать ошибку в `calculate_risk_metrics`.
- **Ожидаемое поведение**:
  - fallback на `get_portfolio_summary` при доступности;
  - рост `error_count`, но без критического падения графа.

## 5) Quick Troubleshooting

### Проблема: отсутствуют ключи в `.env`

- Проверить копирование `.env.example` -> `.env`.
- Убедиться, что заполнены `YANDEX_CLOUD_API_KEY`, `YANDEX_CLOUD_FOLDER`, `YANDEX_CLOUD_MODEL`.

### Проблема: недоступен ClickHouse

- Для локального демо включить `USE_MOCK_CLICKHOUSE=true`.
- Проверить `CLICKHOUSE_HOST/PORT/USER/PASSWORD`.

### Проблема: не стартует Streamlit/CLI

- Проверить установленное окружение (`uv sync --group dev`).
- Для CLI использовать `python -m ui.cli chat`.
- Для Streamlit использовать `streamlit run ui/streamlit_app.py`.

### Проблема: ошибки внешних API

- Проверить доступность сети.
- Перезапустить соответствующий MCP-сервер.
- Для демонстрации использовать mock-режим и тестовые сценарии.
