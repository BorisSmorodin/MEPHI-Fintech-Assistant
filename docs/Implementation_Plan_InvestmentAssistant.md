# Детализированный план реализации Investment Assistant

## 1. Цель и границы реализации

- Цель: реализовать прототип инвестиционного ассистента по архитектуре `LangGraph + MCP` с тремя MCP-серверами, оркестратором и двумя UI.
- Границы: только требования из `docs/TZ_InvestmentAssistant.md` версии 1.0.
- Ключевые результаты:
  - Рабочие MCP-сервисы `market_server`, `news_server`, `analytics_server`.
  - Рабочий оркестратор с маршрутизацией запросов и суммаризацией ответа.
  - UI: CLI и Streamlit.
  - Покрытие тестами: юнит + интеграционные + E2E-сценарии.
  - Соблюдение требований безопасности (SQL, prompt injection, секреты).

## 2. Принципы декомпозиции работ

- Каждая задача декомпозирована до минимально исполнимого шага.
- Каждая подзадача имеет проверяемый артефакт.
- Внутри модулей: сначала интерфейсы/контракты, затем реализация, затем тесты.
- Нефункциональные требования (логирование, ошибки, таймауты, кэш) внедряются сразу, а не в конце.

## 3. Критерии готовности проекта (Definition of Done)

- Все модули соответствуют структуре проекта из ТЗ.
- Все публичные функции типизированы и снабжены docstring (Google-стиль).
- MCP-инструменты имеют корректные docstring-описания для LLM.
- Все настройки берутся только из `config/settings.py`.
- Нет использования `print` и `logging.basicConfig`, только `structlog`.
- Проходят:
  - юнит-тесты;
  - интеграционные тесты;
  - E2E-сценарии из ТЗ.
- Реализованы ограничения безопасности:
  - `execute_analytics_query` исполняет только `SELECT`;
  - ограничение `LIMIT 1000`;
  - таймауты и read-only режимы;
  - экранирование потенциально инъекционного новостного контента.

## 7. Риск-реестр реализации

- Риск: нестабильность внешних API (MOEX, RSS).
  - Митигация: кэш, retry, graceful degradation, фикстуры.
- Риск: низкая воспроизводимость расчетов из-за разнородных данных.
  - Митигация: детерминированные тестовые данные, фиксированные сценарии.
- Риск: некорректная маршрутизация planner.
  - Митигация: unit-тесты routing + golden-case тесты.
- Риск: SQL-инъекции в `execute_analytics_query`.
  - Митигация: AST-валидация, запрет DML/DDL, read-only user, timeout.
- Риск: задержки ответа при комплексных запросах.
  - Митигация: ограничение шагов, параллелизм внутри узлов, кэш инструментов.
